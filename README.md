# 业绩计算工作台（Web）

用于跨境业务按订单维度做业绩核算：

- 上传订单表
- 上传订单明细表（支持多个文件追加）
- 上传放退款订单明细表（支持多个文件追加）
- 上传运费表
- 按订单号筛选并整合
- 导出新的 Excel 结果文件

## 功能规则

系统实现了当前定义的 4 个步骤：

1. 从订单明细表筛选出订单表中存在的订单数据，并按费用列拆分成收支明细
2. 从运费表筛选出订单表中存在的运费数据（交易单号匹配订单号），输出实际运费表
3. 对订单表标记是否在订单明细拆分结果中有记录
4. 整合三张表并按订单号排序

## 订单明细多文件支持

由于订单明细表一次通常只覆盖部分周期，页面支持多次追加上传并自动合并：

1. 在订单明细表卡片中反复点击“追加订单明细 Excel”
2. 每个文件都可以单独选择工作表和“关联订单字段”
3. 系统会将所有订单明细文件合并后再筛选订单范围
4. 在字段映射区勾选需要参与计算的费用列（支持多选）
5. 可删除某个已上传文件后重新计算

## 页面使用流程

1. 订单表上传区块：一次可上传多个文件（每个文件可选工作表）
2. 订单明细表区块：一次可上传多个文件（每个文件可选工作表、关联订单字段）
3. 放退款订单明细区块：一次可上传多个文件（每个文件可选工作表、关联订单字段）
4. 金掌柜运费表区块：一次可上传多个文件（每个文件可选工作表）
5. 在字段映射中勾选订单明细费用列与放退款费用列
6. 点击“执行筛选与整合”
7. 点击“导出结果 Excel”

## 导出结果（6 个 Sheet）

- 业绩明细表
- 订单聚合表（按订单一行，含收入校验相关字段）
- 收入校验（订单明细收入 vs 放退款明细收入 对比）
- 订单表有但收支缺失（订单表存在但订单明细无记录）
- 仅订单明细有（在订单明细表出现、但放退款明细未出现）
- 仅放退款明细有（在放退款明细出现、但订单明细未出现）

## 业绩明细表输出字段

当前主输出 Sheet 为 `业绩明细表`，字段如下：

- 订单号
- 订单状态
- 收支类型
- 变动金额
- 费用项
- 物流履约单号
- 运单号
- 计费金额合计CNY
- 计费金额合计USD

说明：

- 运费表中的金额视为支出，导出时会自动取反（统一转为负数）。
- 订单明细表支持多文件追加上传，系统会先合并并按费用列拆分再筛选。
- 系统会对比订单明细与放退款明细的订单差异，输出双向差异清单便于排查。
- 订单聚合收入按业务口径计算：订单收入 = 订单明细放款金额合计 - 订单明细平台分账金额合计。
- 放退款收入校验按业务口径计算：放退款收入 = 放退款金额项合计 - 放退款其他费用合计，并与订单收入对比差异。
- 最终收入按业务口径计算：最终收入 = 订单收入 + 运费合计（运费支出为负数）。
- 费用列按列名自动识别正负方向：`xx退回/返还/赔付` 视作收入，佣金/服务费/营销/cashback/分账/退款等默认视作支出。
- 页面会展示订单数量、收入合计、支出合计、物流影响、净额等汇总指标。

## 本地运行

```bash
npm install
npm run dev
```

默认会走本地联调模式：

- 前端开发地址：`http://localhost:5173`
- 前端请求基址：`/api`（由 Vite 代理）
- 代理目标：`http://127.0.0.1:3100`

### 前后端本地联调（推荐）

1. 启动后端（`workbench-tenant-server`）

```bash
cd ../workbench-tenant-server
cp .env.example .env
npm install
npm run dev
```

2. 启动前端（本项目）

```bash
cp .env.example .env
npm install
npm run dev
```

3. 首次本地初始化超级管理员（后端目录执行）

```bash
npm run create:super-admin -- --username=admin --email=admin@local.dev --password=Admin123456
```

4. 使用上面账号在前端登录调试即可。

说明：

- 若你此前在浏览器缓存过线上 API 地址，本项目在开发模式下会自动优先切回本地 `/api`。
- 如需临时连远端服务，可在前端 `.env` 配置 `VITE_WORKBENCH_API_BASE_URL` 覆盖。
